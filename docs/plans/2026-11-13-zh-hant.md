## Design

D1 One String Catalog, `Localizable.xcstrings` in the Ice target's resources, source
language `en`, one translation `zh-Hant`. `knownRegions` gains `zh-Hant`. English text
stays the key, so nothing English changes.

D2 Strings the compiler cannot see (F3): AppKit titles and alert texts become
`String(localized:)`; `Permission` titles and details likewise; run-time
`LocalizedStringKey(rawValue)` keys are entered in the catalog by hand. Interpolated
AppKit strings become format keys (`"Show %@ Section"`), the section name itself
localized first.

D3 IceCore stays pure (F4). Its sentences become templates with `%@` placeholders, and
every message API takes a `localize: (String) -> String` parameter, default identity.
IceCore substitutes the placeholders itself (a small pure formatter, no Foundation).
The app passes a lookup in its own bundle's `Localizable` table; the templates are
entered in the catalog by hand.

D4 The language option (F5). General settings gain "Language": System, English,
繁體中文. It writes the app's own `AppleLanguages` (`["zh-Hant"]`, `["en"]`, or removes
the key for System), the standard per-app language mechanism (the same one System
Settings > Language & Region > Applications uses), and offers "Relaunch Ice" because
bundles pick their language at launch. The pure mapping (option <-> stored value,
including unknown stored values read as System) lives in IceCore with tests.

D5 Words. Product names stay as they are: "Ice", "Ice Bar". Apple's zh-Hant terms:
選單列 (menu bar), 選單列項目 (menu bar item), 設定 (settings), 輔助使用 (Accessibility),
螢幕錄製 (Screen Recording; the macOS 27 Privacy pane's exact label TBD, read before
writing), 快速鍵 (hotkey), 結束 (Quit), 區段 (section), 隱藏 / 永遠隱藏 (hidden /
always-hidden), 外觀 (appearance), 一般 / 進階 / 關於 (General / Advanced / About).

D6 Completeness check. `docs/plans/checks/check-zh-hant.sh`: after a Debug build, every
extracted key (F2) and every hand-entered key list (D2, D3) has a `zh-Hant` value in
the catalog that is not empty and not marked `needs_review`; exit non-zero otherwise.

Not done: Simplified Chinese, Japanese; Sparkle, the updater and other parts removed
on macOS 27; the README stays English (a short note on the option is added).

## Tasks

T1 IceCore (TDD): the template formatter (`%@` in order, a literal `%%`, too few or
too many arguments never crash); each message API with a fake `localize` returns the
fake's text with names substituted; identity reproduces today's English byte for
byte (existing tests unchanged); the language mapping of D4. Coverage of touched files
>= 80%.
T2 App: D2 conversions; D3 wiring at the two status call sites
(`GeneralSettingsPane`, `MenuBarLayoutSettingsPane`) and `IceBarHidingCoordinator`;
D4 picker and relaunch.
T3 The catalog with every zh-Hant value; D6 script passes; Debug and Release builds.
T4 Version 1.1.0 (`MARKETING_VERSION`).

## Live check (on the daily Ice, after T1-T4 pass)

Build the signed Release, archive the installed 1.0.1, install. Then, with automation
only (`settingsdrive axdump`, screenshots to `~/IceReverse-evidence/<run id>/`):
- L1 Language System: Settings read in English, as 1.0.1 (the owner's list, F5);
- L2 Language 繁體中文 chosen in the pane, Ice relaunched: every pane's controls and the
  right-click menu read in Chinese; no catalog key left in English except product names;
  the hiding status line in Chinese;
- L3 Back to System: English again after relaunch.
Pass: L1-L3. Rollback: the archived app by `ditto`; `defaults delete
io.github.tk88101.Ice AppleLanguages`.

## Risks

- R1 Text length: Chinese is usually shorter; a fixed-width control may still clip.
  L2's screenshots are looked at for clipping.
- R2 A key typed by hand (D2, D3) that drifts from its English source is silently
  English at run time. D6 and T1's identity tests catch the IceCore side; the app side
  is caught by L2's "no English left".
