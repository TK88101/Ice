## Design

D1 One String Catalog, `Localizable.xcstrings` in the Ice target's resources (a member
of the target, copied by its Resources phase; checked in the built bundle as
`zh-Hant.lproj/Localizable.strings` or the compiled catalog), source language `en`, one
translation `zh-Hant`. `knownRegions` gains `zh-Hant`; the Ice target's Debug and
Release gain `LOCALIZATION_PREFERS_STRING_CATALOGS = YES` (the XPC target has it).
English text stays the key, so nothing English changes.

D2 Strings the compiler cannot see, all of them listed here (inventory by grep of the
UI sinks `Text(<non-literal>)`, `LocalizedStringKey(<expr>)`, `NSMenuItem(title:`,
`.title =`, `messageText`, `informativeText`, plain-`String` model fields shown in
views):
- run-time keys from enum raw values: `NavigationIdentifier.localized` (pane names),
  `Text(imageSet.name.rawValue)` (the icon set names, `GeneralSettingsPane:163`):
  entered by hand, one key per case;
- run-time keys built from numbers: `rehideIntervalKey` (`GeneralSettingsPane:28`),
  `formattedToSeconds` (`AdvancedSettingsPane:18`): the existing `== 1` branch picks one
  of two static format keys, `"%@ second"` and `"%@ seconds"`, built as
  `String(localized: "\(formatted) second")` / `"... seconds"` with `formatted` the
  same `interval.formatted()` string as today (so English is unchanged and the
  argument is a string, `%@`); both translate to `%@ 秒`. Chinese has no plural, so no
  plural variation is needed. The spacing slider's numeric label (`GeneralSettingsPane:24`)
  is a bare number: shown with `Text(verbatim:)`, not a key;
- run-time keys from names: `MenuBarSection.Name.displayString` and `.localized`
  (`MenuBarSection.swift:18-37`; also the search panel's section headers,
  `MenuBarSearchPanel:319` and `:325`, which switch to the localized string), and
  `IceWindow` titles (`IceWindow.swift:95-104`, `titleKey`, the Settings window's
  visible title): every case entered by hand;
- AppKit: `ControlItem` menu (settings, quit, search, "Show/Hide %@ Section" with the
  section name localized first), `MenuBarManager` menu, `NSAlert` texts in
  `MenuBarItemManager:1793`, `LayoutBarItemView:101-110`, `Migration:248`, the
  appearance editor panel's window title (`MenuBarAppearanceEditorPanel:34`, a visible
  title): `String(localized:)`;
- `Permission` titles and details: `String(localized:)`.
Not translated, on purpose: the window titles of panels that never show a title bar
(`IceBar` "Ice Bar", `MenuBarOverlayPanel`), item names (other apps' own), and
`logSummary` and every log line (D3).

D3 IceCore stays pure and owner-facing text becomes data (F4). IceCore gains
`OwnerMessage` (`template: String`, `arguments: [String]`, `Equatable`; the template
is today's English sentence with `%@` where a name goes) and a pure `rendered(with
localize: (String) -> String)` that looks the template up and substitutes the
arguments (no Foundation). `IceBarHidingStatus` and `IcePlacementNotice` expose
`ownerMessage: OwnerMessage?`; their English `message` stays, defined as
`ownerMessage?.rendered(with: identity)`, so tests and logs keep their text.
`logSummary` stays unlocalized: it is the lab's parser-facing protocol.
App state stores `OwnerMessage` (`HidingCheckStatus.message` becomes one), the two
panes compare `OwnerMessage` values (not rendered text) to suppress the duplicate
line, and render at the view with the app's bundle lookup. The templates are entered
in the catalog by hand; `OwnerMessage.allTemplates` lists them for D6.

D4 The language option (F5). General settings gain "Language": System, English,
繁體中文. It writes the app's own `AppleLanguages` (`["zh-Hant"]`, `["en"]`, or removes
the key for System), the standard per-app language mechanism (the same one System
Settings > Language & Region > Applications uses), and offers "Relaunch Ice" because
bundles pick their language at launch. The pure mapping (option <-> stored value,
including unknown stored values read as System) lives in IceCore with tests.

D5 Words. Product names stay as they are: "Ice", "Ice Bar". Apple's zh-Hant terms:
選單列 (menu bar), 選單列項目 (menu bar item), 設定 (settings), 輔助使用 (Accessibility),
螢幕錄製 (Screen Recording; the macOS 27 Privacy pane's exact label TBD, read before
writing), 快速鍵 (hotkey), 結束 (Quit), 區段 (section), 隱藏 / 永遠隱藏 (hidden /
always-hidden), 外觀 (appearance), 一般 / 進階 / 關於 (General / Advanced / About).

D6 Completeness check. `docs/plans/checks/check-zh-hant.sh`: after a Debug build, every
extracted key (F2), every hand-entered key (D2's enum cases, `OwnerMessage.allTemplates`
printed by a test helper) has a `zh-Hant` value in the catalog that is not empty and
not `needs_review`; and a grep of the D2 sinks finds no English literal outside
`String(localized:)` / `LocalizedStringKey` except the D2 "not translated" list. Exit
non-zero otherwise.

D7 The lab keeps English. The runners that read Ice's UI by its English titles
(`settings_lab.py` `start_ice`, and any other runner that launches Ice and reads its
windows) pass `-AppleLanguages (en)` on Ice's command line: the argument domain
overrides the app domain whatever `write_settings` imported or kept, so no setup or
teardown of the domain is needed. Their English selectors stay. Their Python tests
check the argument is passed.

Not done: Simplified Chinese, Japanese; Sparkle, the updater and other parts removed
on macOS 27; the README stays English (a short note on the option is added).

## Tasks

T1 IceCore (TDD): `OwnerMessage.rendered` (`%@` in order, a literal `%%`, too few or
too many arguments never crash); each status and notice gives the `OwnerMessage` whose
identity rendering equals today's `message` byte for byte (existing tests unchanged);
`allTemplates` covers every case; `logSummary` unchanged; the language mapping of D4.
Coverage of touched files >= 80%.
T2 App: D2 conversions; D3 wiring (`HidingCheckStatus`, `IceBarHidingCoordinator`,
the two panes' comparison and rendering); D4 picker and relaunch; D7 in the lab runners
(`settings_lab.py` setup/teardown) with their Python tests updated.
T2b L2's harness: `docs/macos-27/probes/visibility/zh_check.py`, built on
`settingsdrive` (`axdump`, `axpress`, the guarded right-click of Ice's icon the
settings pass used): opens Settings from the right-click menu by its Chinese title,
visits each pane by its Chinese name, dumps every control's title, value and help, and
reports any text that is not a zh-Hant catalog value, a product name, an item's own
name, or a number. Its rules tested on synthetic dumps (`test_zh_check.py`).
T3 The catalog with every zh-Hant value; D6 script passes; Debug and Release builds.
T4 Version 1.1.0 (`MARKETING_VERSION`).

## Live check (on the daily Ice, after T1-T4 pass)

Build the signed Release, archive the installed 1.0.1, install. Then, with automation
only (`settingsdrive axdump`, screenshots to `~/IceReverse-evidence/<run id>/`):
- L1 Language System: Settings read in English, as 1.0.1 (the owner's list, F5);
- L2 (`zh_check.py`) Language 繁體中文 chosen in the pane, Ice relaunched: every pane's controls and the
  right-click menu read in Chinese; no catalog key left in English except product names;
  the hiding status line in Chinese;
- L3 Back to System: English again after relaunch.
Pass: L1-L3. Rollback: the archived app by `ditto`; `defaults delete
io.github.tk88101.Ice AppleLanguages`.

## Risks

- R1 Text length: Chinese is usually shorter; a fixed-width control may still clip.
  L2's screenshots are looked at for clipping.
- R2 A key typed by hand (D2, D3) that drifts from its English source is silently
  English at run time. D6 and T1's identity tests catch the IceCore side; the app side
  is caught by L2's "no English left".
